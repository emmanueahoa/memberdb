Software engineer handoff: data contract and counting rules

This standalone dashboard runs offline without dependencies and loads an embedded aggregate snapshot automatically. For integration, replace the embedded snapshot with your API response and call load(snapshot). No import, export, print or demo-reset controls are exposed. The network directory has been removed; the overview always displays all unions, societies and regions without filters or drill-down scope changes.

    

  • One society belongs to exactly one union. Entity IDs must be unique and parent links valid.
    • 

  • Each aggregate row represents one society, member region, required age band and recorded sex/gender category. Count must be a nonnegative integer. Repeated dimension combinations are rejected.
    • 

  • Counts represent unique members assigned to one primary society. If members can belong to multiple societies, deduplicate upstream or supply distinct-count measures. Do not sum overlapping memberships.
    • 

  • Age is required. Valid bands are under18, 18to35, 36to45, 46to60 and 61plus. Missing, null, unknown or invalid age bands are rejected. Derive age upstream from the required birth date at the snapshot date. Youth is 18–35 inclusive; above 60 is 61+. There is no missing-age card or unknown-age chart category.
    • 

  • Percentages use all members in the full network. Age bands sum to the member total. Youth, male, female and above-60 percentages are independent measures and are not additive categories.
    • 

  • Region means member location. Missing region uses unknown. The region chart displays only the top five regions by member count, descending, with alphabetical tie-breaking. Percentages use the full network member total, not the top-five subtotal. Other panels and totals continue to include all regions. Empty entities remain visible in network totals.
    • 

  • Use the sex or gender field actually recorded; demographicField must be Sex or Gender. Gender is required for every aggregate row. Missing, blank, null, unknown and unspecified values are rejected. Preserve valid source categories; no unknown segment or legend item is shown. Gender categories must sum to the full membership total.
    • 

  • The snapshot asOf date remains required internally for consistent age calculations, but no date or region-basis placeholder is displayed in the filter area. Historical trends are omitted until historical data is available.
    • 

  • Default demographic suppression threshold is 5. If any positive demographic category is below threshold, demographic cards and both demographic charts are withheld. Apply authorization and stronger disclosure checks server-side in production.
    • 

  • Rank ties use alphabetical name order. Rankings measure network size, not employee or organizational performance. Society rankings always display the parent union. Top 10 societies use rounded horizontal bars with rank, society name, parent union and exact member count. Bars share a zero baseline and scale to the largest society in the displayed top ten. Names wrap on narrow screens; union labels are never hidden behind tooltips. Rankings remain informational, with no scope changes.
    • 

  • This screen has no filters or reset control. All panels use the complete snapshot. Ranking labels are informational and do not change scope; dedicated filtering belongs to a separate screen. The age-chart scope note and the dashboard footer are not displayed.
    • 

  • Mock entity names and counts are retained for testing. Previously unspecified mock ages are assigned to the 46–60 band so every member has an age band; overall membership, union totals, society totals, regions are unchanged. Previously unknown mock gender rows are assigned alternately to Male and Female and merged into matching aggregate dimensions solely to complete the fictional dataset. Gender subtotals therefore change, but all society, union, age and region totals are preserved. Production gender must come from actual required source values, never inferred. Production ages must come from actual birth dates, never inferred.
    • 

  • Production needs authentication, authorization, audit controls and server-side validation. Source strings are escaped before rendering. The embedded mock snapshot is not a live connection. The header breadcrumb and sidebar branding have been removed, and the sidebar explanatory text is hidden; the remaining layout and panels are retained.
